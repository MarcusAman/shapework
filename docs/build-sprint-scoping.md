# Build Sprint Scoping & Deliverables

The Build Sprint Planner bridges the discovery phase and the implementation phase. It creates clear boundaries around implementation fees and out-of-scope tasks.

## 1. Scoping Fields
Each Build Sprint record defines:
- **Scope Inclusions**: Specific workflow templates and rules logic being configured.
- **Out-of-Scope Inclusions**: Features requiring custom development or third-party license configurations.
- **Deliverables**: In-app assets (forms, checklists, email templates) created.
- **Estimated Fees**: Fixed fee ranges for the specific build phase.
- **Active status**: Draft $\rightarrow$ Proposed $\rightarrow$ Approved $\rightarrow$ In Progress $\rightarrow$ Shipped.

## 2. Reusable IP vs. Custom Integrations
- **Reusable IP**: shapework. templates, FAQ deflection rules, roles mappings.
- **Custom Integrations**: Custom endpoint integrations not supported by active MCP servers, or custom website design widgets.
- **hypercare**: Each build sprint includes 30 days of post-launch maintenance.
